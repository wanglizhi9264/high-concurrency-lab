# Feature Specification: 010 学习工程精修

**Feature Branch**: `feature/010-learning-craft`  
**Created**: 2026-10-29  
**Status**: Draft  
**Input**: 参考经典项目，打磨代码可读性和策略，并交付通俗、对应源码的高质量学习资料。

## User Scenarios & Testing

### US1 — 看懂策略而非猜测数字（P1）

学习者能在明确入口找到缓存过期、重试间隔、停止重试的规则。
独立验证：规则边界测试不依赖基础服务。

1. 给定首次到第五次失败，能读出等待多久、何时停止，原有任务结果不变。
2. 给定缓存有效期及随机偏移，能读出实际过期范围，绕过和失败回源保持原义。

### US2 — 顺着真实业务学习基础（P1）

学习者从一本本地中文手册进入源码，完成小实验并回答解释性问题。
独立验证：每章有源码入口、具体操作、预期现象、反例、答案和精选原始参考。

1. 从一次请求串起协议、异步、资源、SQL、事务、缓存、任务与性能。
2. 区分已实现能力、原理介绍和未来练习，不误以为已有认证或生产高可用。

### US3 — 维护者能安全修改（P2）

维护者能依照规则定位修改层、选择回归测试，不破坏历史实验。
独立验证：现有真实缓存和任务集成测试通过，历史证据不变。

1. 调整策略前能找到约束和失败路径；外部接口、持久化状态和证据不变。

### Edge Cases

非法有效期、负偏移、偏移超过范围、非法重试次数被明确拒绝；任务最后一次失败停止重试；业务前置条件错误不自动重试；取消不被吞成正常降级。无法运行服务时如实记录未验证项。

## Requirements

- **FR-001**: 保持已有接口、默认策略、事务和数据边界；不迁移、不清空、不改写历史测量。
- **FR-002**: 缓存有效期与任务重试决策具备命名清楚、可独立验证的规则入口；执行层保留 I/O 与事务所有权。
- **FR-003**: 中文手册覆盖请求/异步、SQL/事务、缓存、任务、性能、排障、安全部署缺口及算法学习边界；解释术语，包含源码、操作、结果、反例、自测答案。
- **FR-004**: 参考少量经典项目/官方资料，明确借鉴点、阅读范围和不照搬的部分；不新增运行依赖。
- **FR-005**: 提供维护指南、能力矩阵和后续优先级；本轮是现有链路精修，不声称补齐上一轮全部生产缺口。
- **FR-006**: 执行回归、真实服务验证、只读分析及收敛，通过独立 PR 交付；记录实际结果。

## Success Criteria

- **SC-001**: 两类策略都有可验证的边界与失败决策，已有成功/失败语义不变。
- **SC-002**: 学习入口能到达至少八章正文，每章上述六项学习材料完整，仓库内相对文件链接可解析。
- **SC-003**: 质量检查及真实缓存/任务回归通过；对未执行的性能或生产验证明确说明。

## Key Entities

缓存有效期规则、任务失败决策、章节、源码入口、学习练习；不增加数据库实体。

## Assumptions

以 Python 业务后端为主；初学者先会基础语法。保持模块化单体；鉴权/真实商品更新/生产部署仍需要后续独立规格。文档明确缺口，既提供入门解释，也不假装已有生产实现。
