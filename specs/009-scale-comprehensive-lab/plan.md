## Query protocol
Baseline runs first and is saved exclusively before schemaadvance. For each twin/phase: ANALYZE TABLE, actual schema/stats, source/window/env, known cursorlookup separatelytimed, fixed SQL with boundparams, warmup1 thenrepeats, EXPLAIN ANALYZE TREE and EXPLAIN FORMAT=JSON. Cases: primary-key control, singleuser orderedID, user/time projection includingtotal/status, globaldeepOFFSET and paired keyset (created_atDESC,idDESC), pruning-compatible time-range aggregate, non-pruning id-only predicate. Equivalent SQL/result hashes and same offset/cursor acrossphases/twins; exactpageIDs OFFSET==keyset. No callerSQL.

Coverage proof uses actual JSON using_index or EXPLAIN Extra Using index; Using index condition is not coverage. Preserve original plan if optimizer chooses anotherpath; assertions never force a false covering claim. Partition lists come from EXPLAIN JSON optimizer selection, with actual TREE row/timing observations separately. Compare range-compatible and incompatible selectedpartitions; no forced scan hints to exaggerate benefit. Access rows=sum(actual iterator outputrows×loops) at accessnodes, not physicalI/O; never sum nested node times. Client execute/fetch wall separate from server iterator timings.

Writes after all immutable querymeasurements: identical50000synthetic rows per initiallyempty baseline/compound/cover probe (test1000), per-batch actualINSERT+COMMIT samples, rotate layoutorder eachbatch, record total/rows/s/P50/P95/P99 and exact finalcounts/digest/schema/size. Data generation outside these SQLtimers. Shared caches/order effects remainconfounders. Claim explicitly limited to fresh-table50k incremental bulk writes, not writeamplification into a million-existing-row table. No speculative sharding: ADR/report evaluate routing, cross-shardtransactions, globaluniqueness, joins, rebalancing andoperations against actual single-instance results.
