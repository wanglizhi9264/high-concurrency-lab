# Data model
DurableTask is authoritative, immutable intent + changing state/lease/attempt count. queued→running→succeeded; running→retry_wait→running; running→failed when exhausted/nonretryable. Expired running ownership records an abandoned attempt, then new running or terminal failed. Terminal tasks never reset. retry_of links a newly created successor to a failed original.
Task+Outbox creation and attempt/result transitions are explicit SQL transactions. Receipt UNIQUE order_id is immutable, Task.result_receipt_id references it. Outbox may publish repeatedly. Task lease token is private and checked with database UTC time at final mutation.
Attempt.started_at is durable claim time; handler_ms is measured monotonic handler phase. Crashed attempt finished_at/handler_ms null; abandoned_at is recovery observation. Events record actual persisted transitions, not inferred animations. UTC DB timestamps serialize as UTC, not local-browser naive times.
ControlledFaultPlan is configuration (fail_first_attempts0..5,delay_ms0..5000), not measured data. Actual attempt failure/timeouts are measured outcomes.
TaskDetail contains public Task, Outbox confirmation, <=5attempts, latest100events, optionalReceipt, fixed CLI command/source/definitions. No lease token or credentials. QueueSnapshot has collection time/window/source, retained_entries/pending/group_lag/PTTL nullable, group_ready and independent DB counts. Success does not imply observed ACK.
