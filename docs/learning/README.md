# 把后端学到能解释、能修改、能排错

这是一本围绕本仓库编写的中文学习手册，不要求先学一堆中间件。你只需要会 Python 基础语法、能运行项目。读完的目标：遇到重复请求、库存不足、缓存故障、任务重投时，能画出顺序、预测数据库变化，再用实际测试确认。

## 怎么学

每次只学一章：先回答自测，再读解释；打开源码沿调用顺序读，不从最大文件第一行硬啃；运行一个小测试，写下看到的结果。耗时依赖本机，教程不给你预设“应该快多少”。命令从仓库根目录执行，单元测试不需要启动数据库。真实集成测试必须按现有指南配置 owned test 库和显式开关，不能只看到 skipped 就算学完。

## 能力地图：实现与原理不要混淆

| 能力 | 本项目状态 | 学到什么程度就够本阶段 |
|---|---|---|
| HTTP/分层/校验 | 已实现；协议原理见第1章 | 能沿请求找到 SQL 和响应，区分错误来源 |
| Python 异步/池/资源 | 已实现；运行时原理见第2章 | 能解释等待、阻塞、取消与关闭 |
| 建模/索引/分页 | 已实测万行、百万009；旧002独立保存 | 能读计划、设计稳定分页，不以行数决定分片 |
| 事务/锁/库存幂等 | 已有真实失败与并发测试 | 能解释不变量、回滚、重放和未知提交 |
| 缓存读/TTL/旧回填 | 已实现 | 能解释 lease 与 generation 各挡哪种竞态 |
| 商品修改→缓存失效可靠闭环 | **未实现** | 先理解提交与失效之间的失败窗口 |
| 可靠任务/恢复 | 已实现固定 receipt handler | 能解释 Outbox、重复投递、最终 fence、ACK |
| 压测/Trace/资源证据 | 已实现实验能力 | 不把失败 RPS、单次短测当生产容量 |
| 登录/用户归属授权 | **未实现** | 第8章是设计练习，不代表接口已安全对外开放 |
| 生产发布/监控告警/备份恢复 | **未完成闭环**；已有 Dockerfile/CI/探针 | 先能在隔离环境部署、定位、回滚、恢复 |
| 算法/操作系统/网络基础 | 项目只能提供例子 | 另练基础题，不为刷题改业务 |

后续优先级：认证与订单归属 → 商品更新/失效 → 入口过载保护 → Linux 发布/监控/恢复。每项另开 SDD，不能把这张表当已交付清单。暂时不需要微服务、Kubernetes、分库分表或同时学习多套 MQ。

## 实验安全约定

002–009 原始记录是历史证据，阅读不修改。练习不执行 DROP/TRUNCATE/FLUSH，不复制凭据进笔记。库存/任务使用测试库及新 UUID，保留状态和失败历史。读索引计划不需要运行百万造数；`EXPLAIN ANALYZE` 会真实执行查询，先确认是固定 SELECT 和正确实例。参考[现有运行指南](../guides/business-lab.md)、[测试库与 worker](../guides/worker-lab.md)。
