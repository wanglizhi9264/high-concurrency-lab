# ADR0007 — 可比分析副本、索引演进与分区评估

接受，2026-10-25，009实现前。MySQL业务表/002记录不变；009在独立owned数据库和独立Alembic上下文中建立分析副本。两张查询表同列、同PK(id,created_at)、同阶段索引，仅一张季度RANGE COLUMNS分区。分区InnoDB不支持业务外键，所有唯一键须含分区列，因此不假装这是原订单表的无损替代；id单列唯一由确定性生成与流式DB摘要校验，不是独立UNIQUE(id)。

先保存ix_user单列基线，再通过迁移替换用户时间联合索引并加全局时间索引，最后替换为含total/status的覆盖候选索引。每一步保存真实SHOW CREATE/INDEX、SQL/参数、TREE和JSON；只有实际计划using_index/Using index证明覆盖，ICP不是覆盖。查询数据全程不改，OFFSET/keyset按created_atDESC,idDESC同页，定位游标另计。

三张空写入探针最终分别保留对应索引，轮换相同50k数据批次执行顺序并实际提交，单独测execute+COMMIT/空间/索引构建。避免追加到查询表破坏跨阶段对照。结论限于空表起始50k增量写，不代表百万存量写放大。预建多个百万副本不必要；两表演进减少资源且保留阶段证据。

分区同时测时间范围裁剪与id-only不裁剪的真实selected partitions，不能以数据量大就宣称分区有效。暖缓存/阶段先后/共享实例/统计估算/小样本均保留限制。千万级需显式optin，不是启动前提。没有证据时不引入分库分表；报告评估路由、全局唯一、跨分片事务/JOIN、迁移再平衡与运维成本。

真实干净克隆采用新Compose项目/端口/卷，所有子进程继承相同作用域；避免复用旧预览。仅停止自己创建的进程和项目，保留卷和结果。凭据新生成在ignored.env，不进入记录。
